Cloud deployment: CI/CD Pipeline


Pipeline of testing and deployment in Github

I have planned the development environment to be automated via the Github repository.

Two branches in the repository are included in the pipeline: main and AWS-Elli. Main branch will deploy to the MAIN EBS environment, when AWS-Elli branch will deploy to the TEST EBS environment. The use case with this is, that we would first deploy to the testing environment and if that goes successfully, we can deploy to the main environment. The main environment would be the one that is standing and live all the time and would not receive constant updates. The test environment can be used somewhat freely to test the deployments.

Summary of the Workflow flow
  1. Triggered on a push to the main or AWS-Elli branch.
  2. Runs end-to-end tests (e2e_test.yml).
  3. Prepares backend and frontend components for deployment.
  4. Packages the application into a deployment zip.
  5. Deploys to AWS Elastic Beanstalk and configures runtime environment variables.
If the end-to-end tests fail, the deployment process will stop.

e2e_tests.yml


Reusable Workflow: This workflow can be called by other workflows (workflow_call event).
Secrets Injection: Uses MONGODB_URL, JWT_SECRET and REFRESH_TOKEN_SECRET secrets for configuring the environment.


Setting up the environment

Checkout code: Pulls the code repository to the runner using actions/checkout.
Create .env file: Uses the SpicyPizza/create-envfile action to generate an .env file for the database connection to work in the Server directory.


Preparing server

Noje.js setup: Installs Node.js (v20) for the runner.
Procfile creation: Creates a Procfile in the Server directory for development configuration.
This is the variable that changes the code structure to be either local development or cloud. Environment set as “development” will use localhost:8080 and be run as it was local. Environment set as “production” will set up the code to use the cloud environment’s URL and ports. For the end-to-end tests we only need it to run in the Github virtual machine so setting it to development works for this purpose.
Start server: Installs server dependencies and starts the server application in development mode, running it in the background.


Preparing Client

Install dependencies: Installs the client application's dependencies
Build client: Builds the client application.
Start Client: Starts the client application in the background.


Wait for services
Uses a wait action to pause execution for 30 seconds, allowing both the server and client to become ready.


Run Cypress tests
Executes end-to-end tests using the cypress-io/github-action.
Specifies the Cypress spec file to run (cypress/e2e/spec.cy.ts).


Artifact storage
Uploads Cypress test screenshots and videos as artifacts for debugging. Captured only if the tests fail.



cicd.yml


This is the “main” yml file that handles the deployment to the EBS environment.


Triggers: Runs when code is pushed to the main branch (or a specified branch).


Integration with end-to-end tests: Calls and waits for the e2e_test.yml workflow to ensure the application passes all tests before deployment.


Executes only if call-e2e_test succeeds (needs: [call-e2e_test]).


Pulls the source code from the repository to the runner.


Configuring AWS CLI
Sets up AWS credentials and region using the aws-actions/configure-aws-credentials action.
Ensures access to AWS services like Elastic Beanstalk.


Setup Node.js
Installs Node.js (v20) to prepare the environment for running Node-based applications.


Backend preparation
Installs dependencies for the Server component using npm install.
Creates a Procfile to define how the server should run in production.


Frontend preparation
Installs Angular CLI and all dependencies for the Client component.
Builds the Angular project in production mode.


Generate deployment package
Zips the backend (Server), frontend (Client), and necessary files (Procfile, package.json) into a deployment package, excluding unnecessary files like node_modules.


Vefifying
Lists the contents of the deployment package to ensure it contains all required files.


Deploying to AWS Elastic Beanstalk
Uses the beanstalk-deploy action to upload and deploy the package to AWS EBS.
Sets the version label to the current Git commit hash for tracking.


Set environment variables using AWS CLI
Configures MONGODB_URL, JWT_SECRET and REFRESH_TOKEN_SECRET environment variables for the EBS environment using the AWS CLI.
This takes place after the first deployment is up and running.
